How the AI triage stage is built

In

Each finding plus the lines of code around it

Claude on Amazon Bedrock

Asked for priority, exploitability and a concrete fix

Out

One typed record per finding, checked against a schema

Secrets are masked before anything leaves the machine.

Scanner text is data, never instructions to the model.

Output is validated. Unknown finding ids are dropped.

A rule table takes over if the model is unavailable, and says so.

AI-Driven DevSecOps · ATAL FDP 2026

The top row is the happy path: findings with a few lines of surrounding code go in, the model is asked three specific questions, and it must answer in a fixed structure, so the next stage reads fields instead of parsing prose. The bottom half is what makes it safe to put in a pipeline, and it is the part to emphasise with students. One: credential lines are masked before the request is sent; our own unit test caught a case where a neighbouring line leaked a secret into the prompt. Two: code comments and scanner messages can contain text written by an attacker, so the prompt tells the model to treat them as content. Three: we never trust the answer blindly; ids the model invented are discarded and gaps are filled. Four: the pipeline still works without the model and labels the result as rule-based.
