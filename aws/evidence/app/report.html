AI triage summary

This release must not ship: the service has several remotely exploitable remote-code-execution paths on public routes (shell command injection in /ping, pickle deserialization in /cart/restore, unsafe YAML in /config, and the Werkzeug debug console bound to 0.0.0.0), plus SQL injection on login and AWS/database credentials committed to source. The Kubernetes deployment runs the container privileged on the host network, so any one of those code flaws becomes a full node compromise, and outdated Flask/Werkzeug/Jinja2/PyYAML/requests packages add known CVEs. Fixing the P0/P1 items (rotating the leaked credentials, patching the five dangerous routes, disabling debug, upgrading dependencies, and hardening the deployment manifest) is roughly a few days of focused work, after which the remaining items can be scheduled.
